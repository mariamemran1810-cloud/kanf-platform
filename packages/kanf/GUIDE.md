# دليل استخدام منصة كنف

دليل كامل بالعربية للاستخدام اليومي وإدارة المنصة.

---

## 1) التشغيل

```bash
# من جذر المستودع
bun install
bun run dev:kanf          # = bun run --cwd packages/kanf dev

# أو من داخل مجلد الباكدج
cd packages/kanf
bun run dev
```

افتح: **http://localhost:4040**

### متغيّرات التشغيل

| المتغيّر | الوصف | الافتراضي |
| --- | --- | --- |
| `KANF_PORT` | منفذ الخادم | `4040` |
| `KANF_DB` | مسار ملف قاعدة البيانات | `kanf.db` |
| `KANF_SECRET` | مفتاح توقيع الجلسات (إلزامي في الإنتاج) | قيمة عشوائية لكل تشغيل |
| `KANF_AI_BASE_URL` | عنوان واجهة النموذج | `https://api.openai.com/v1` |
| `KANF_AI_API_KEY` | مفتاح API | — (وضع العرض) |
| `KANF_AI_MODEL` | اسم النموذج | `gpt-4o-mini` |

> ✅ بدون `KANF_SECRET` يولّد الخادم مفتاحاً واحداً ويحفظه داخل `kanf.db`،
> فتبقى الجلسات سارية بعد إعادة التشغيل. ضبط `KANF_SECRET` في الإنتاج
> (خاصة عند توفر قواعد بيانات متعددة أو خلف موازي) لضمان ثبات التوقيع.

### مثال تشغيل كامل

```bash
KANF_SECRET="غيّري-هذا-النص-عشوائياً" \
KANF_AI_API_KEY="sk-..." \
KANF_PORT=8080 \
bun run --cwd packages/kanf start
```

### محركات الوكيل

يستطيع ردّ الوكيل أن يأتي من ثلاثة محركات، ويُجرَّبها بالترتيب حتى ينجح أحدها:

| المحرك | متى يعمل | ملاحظات |
| --- | --- | --- |
| **`opencode`** | عند وجود مصدر OpenCode في المستودع أو تنفيذية `opencode` على النظام | وكيل كامل بأدوات حقيقية (قراءة/بحث/تحرير الملفات) |
| **`openai`** | عند ضبط `KANF_AI_API_KEY` | واجهة متوافقة مع OpenAI، مباشرة وسريعة |
| **`demo`** | دائماً | ردود توضيحية بلا إنترنت — الملاذ الأخير |

| المتغيّر | الوصف | الافتراضي |
| --- | --- | --- |
| `KANF_ENGINE` | `auto` \| `opencode` \| `openai` \| `demo` — الوضع الصريح لا يسقط تلقائياً | `auto` |
| `KANF_ENGINE_MODEL` | موديل المحرك بصيغة `provider/model` | موديل OpenCode الافتراضي |
| `KANF_ENGINE_DIR` | مجلد عمل الوكيل (المساحة التي يقرأ ويعدّل فيها) | مجلد التشغيل |
| `KANF_ENGINE_TIMEOUT_MS` | مهلة تنفيذ المحرك | `120000` |
| `KANF_ENGINE_AUTO` | `1` للسماح بتنفيذ الأوامر وتعديل الملفات بلا استيضاح | غير مضبوط (يرفض الصلاحيات) |
| `KANF_OPENCODE_BIN` | مسار صريح لتنفيذية `opencode` | تُكتشف تلقائياً |

**تشغيل محرك OpenCode بمزوّد خاص** (يُفضَّل):

```bash
KANF_ENGINE=opencode \
KANF_ENGINE_MODEL="anthropic/claude-sonnet-5" \
OPENCODE_API_KEY="..." \
bun run --cwd packages/kanf start
```

> الوضع `auto` لا يجرّب محرك OpenCode إلا إذا كان مهيّأً فعلاً
> (`OPENCODE_API_KEY` أو `KANF_ENGINE_MODEL` أو مزوّد مكتوب في
> `~/.config/opencode/opencode.jsonc`)، حتى لا تتأخر أول رسالة في المنتج
> الافتراضي. بعد أول فشل يُقفَل المحرك لبقية الجلسة فلا يُعاد تأخيره.
>
> الاستجابة تحمل مفتاح `engine` لتخبر العميل بأي محرك أُجيب فعلاً:
> `opencode` أو `openai` أو `demo`.

## 2) الحسابات والأدوار

| الدور | صلاحية |
| --- | --- |
| 👑 **مالك** | كل الصلاحيات + حذف الأعضاء + تعيين «مالك» |
| 🛡 **مشرف** | إدارة الأعضاء والمشاريع والتنبيهات |
| 👤 **عضو** | مشاريعه وساحاته وملفه الشخصي فقط |

### حسابات تجريبية

| الدور | البريد | كلمة المرور |
| --- | --- | --- |
| مالك | `owner@kanf.dev` | `Kanf#2026` |
| مشرف | `admin@kanf.dev` | `Kanf#2026` |
| عضو | `member@kanf.dev` | `Kanf#2026` |

> 🧹 لحذف الحسابات التجريبية من الإنتاج: احذف ملف `kanf.db` ثم أنشئ حسابك الأول
> (أول حساب يُنشأ يُسجَّل كـ«مالك» يدوياً عبر `role: "owner"` في `auth.createUser`).

## 3) شاشات لوحة التحكم

### 📊 نظرة عامة
- أربع بطاقات إحصائية: المستخدمون · المشاريع · ساحات الحوار · الرموز المستهلكة
- تنبيهات المنصة (تُنشئها الإدارة)
- آخر ٦ عمليات في سجل النشاط

### 🗂️ المشاريع
- إنشاء / تعديل / حذف / أرشفة
- الحقول: الاسم، الوصف، اللغة، الحالة
- الحذف متاح لصاحب المشروع أو المشرف فأعلى

### 🤖 الوكيل
- إنشاء ساحات حوار متعددة (`＋ ساحة جديدة`)
- الرسائل تُحفظ مع السياق وعدّاد الرموز لكل ساحة
- بدون مفتاح API يعمل في **وضع العرض** ويشرح طريقة التفعيل
- مع `KANF_AI_API_KEY` يستدعي أي نموذج متوافق مع OpenAI

### 🕓 سجل النشاط
- سجل كامل لكل إجراء (دخول، إنشاء مشروع، رسالة وكيل، تعديل عضو…)
- المشرف يرى نشاط **كل** المستخدمين، والعضو يرى نشاطه فقط

### 👥 الأعضاء (للمشرف/المالك فقط)
- تغيير الدور، الخطة، الحالة، وإعادة تعيين كلمة المرور
- «موقوف» يمنع الدخول فوراً
- المالك وحده يستطيع تعيين دور «مالك» أو حذف عضو

### 💳 الاشتراك
| الخطة | السعر/شهر | الحدود |
| --- | --- | --- |
| تجريبي | 0 ر.س | مشروع واحد · ١٠ ساحات |
| احترافي | 4٬900 ر.س | ١٠ مشاريع · ٥٠٠ ساحة |
| مؤسسي | 19٬900 ر.س | بلا حدود · فريق · SSO |

> الربط مع بوابة دفع حقيقية (Stripe / Moyasar / Tap) يمر من `POST /api/billing/upgrade` — نقطة واحدة جاهزة.

### ⚙️ الإعدادات
- تغيير الاسم، اللغة (عربي/إنجليزي)، لون الصورة الرمزية
- تغيير كلمة المرور (٨ أحرف فأكثر)
- تبديل اللغة والمظهر من الشريط الجانبي

## 4) واجهة REST

كل المسارات تحت `/api/` وتحتاج كوكي الجلسة `kanf_session` ما لم يُذكر غير ذلك.

| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `POST` | `/api/auth/signup` | إنشاء حساب |
| `POST` | `/api/auth/login` | دخول |
| `POST` | `/api/auth/logout` | خروج |
| `GET` | `/api/me` | المستخدم الحالي + نصوص الواجهة |
| `PATCH` | `/api/me` | تحديث الملف/كلمة المرور |
| `GET`/`POST` | `/api/projects` | قائمة/إنشاء مشاريع |
| `PATCH`/`DELETE` | `/api/projects/:id` | تعديل/حذف مشروع |
| `GET` | `/api/agent/sessions` | ساحات الوكيل |
| `POST` | `/api/agent/sessions/:id/messages` | إرسال رسالة واستلام رد |
| `GET` | `/api/members` | الأعضاء (مشرف+) |
| `PATCH`/`DELETE` | `/api/members/:id` | تعديل/حذف عضو |
| `GET` | `/api/billing` | الاشتراك والخطط |
| `POST` | `/api/billing/upgrade` | تغيير الخطة |
| `GET` | `/api/activity` | سجل النشاط |
| `GET` | `/api/stats` | إحصائيات اللوحة |
| `POST` | `/api/announcements` | إنشاء تنبيه (مشرف+) |
| `GET` | `/api/health` | فحص الصحة |

### مثال سريع

```bash
curl -c jar -X POST http://localhost:4040/api/auth/login \
  -H "content-type: application/json" \
  -d '{"email":"owner@kanf.dev","password":"Kanf#2026"}'

curl -b jar http://localhost:4040/api/stats
```

## 5) النشر في الإنتاج

```bash
# على الخادم
bun install
KANF_SECRET="..." KANF_PORT=8080 bun run --cwd packages/kanf start
```

خلف عامل ويب (Caddy / Nginx) مع HTTPS إلزامي لأن الجلسات تعتمد كوكي.

### 🟣 النشر على Render (خطة مجانية، بلا بطاقة)

المستودع يحوي `Dockerfile` و`render.yaml` جاهزين، فالنشر خطوتان:

1. افتح الرابط:
   **https://render.com/deploy?repo=https://github.com/mariamemran1810-cloud/kanf-platform**
2. اضغط **Apply** — يقرأ Render ملف `render.yaml` ويبني الخدمة من الـDockerfile.

أو يدوياً: Render ← **New +** ← **Web Service** ← اربط المستودع ←
اختر **Docker** (سيجد `Dockerfile` تلقائياً) ← **Create Web Service**.

الرابط النهائي يكون بصيغة `https://<اسم-الخدمة>.onrender.com`.

**ما يوفّره الإعداد الموجود:**

| البند | القيمة |
| --- | --- |
| أمر البناء | لا شيء — صفر اعتماديات وقت التشغيل |
| أمر التشغيل | `bun run packages/kanf/src/index.ts` |
| المنفذ | `PORT` الذي يمرّره Render (الكود يحترمه) |
| فحص الصحة | `/api/health` |
| `KANF_SECRET` | يولّده Render مرة واحدة ويبقيه ثابتاً |
| `KANF_DB` | `/app/data/kanf.db` |
| زرع البيانات | تلقائي — تُنشأ الحسابات التجريبية عند أول تشغيل |

**ملاحظتان مهمّتان:**

- على **الخطة المجانية** القرص غير دائم: تُعاد قاعدة البيانات إلى حالتها
  عند كل إعادة نشر أو إعادة تشغيل. أضف قرصاً (Disk) عند الترقية ليبقى
  بياناتك، أو استخدم `sync: false` لربط قاعدة خارجية.
- لتشغيل نموذج حقيقي، أضف `KANF_AI_API_KEY` من لوحة Render
  (**Environment** ← إضافة متغيّر). بلاه يعمل الوكيل في وضع العرض.

### ⚠️ مشغّلات GitHub Actions الوراثية

ورث المستودع **26 مشغّلاً** من OpenCode، منها ما يُغلق القضايا وطلبات الدمج
**تلقائياً** ويعمل كل ٣٠ دقيقة. نُقلت كلها إلى
[`.github/workflows-upstream-disabled/`](../.github/workflows-upstream-disabled/) —
وهو مجلد يتجاهله GitHub تماماً. يبقى مُفعّلاً فقط `pages.yml` (نشر الموقع).
التفاصيل وأسباب التعطيل موثّقة في README داخل ذلك المجلد.

### خيارات الاستضافة

| الاستضافة | الطريقة |
| --- | --- |
| 🟣 **Render** | جاهز تماماً — انظر «النشر على Render» أعلاه |
| VPS خاص | `bun run --cwd packages/kanf start` + Caddy |
| Railway / Fly.io | أمر البداية نفسه + متغيّرات البيئة |
| GitHub Pages | موقع تعريفي فقط (workflow `.github/workflows/pages.yml`) |

### الأمان
- كلمات المرور: PBKDF2-SHA256 بـ ٢٠٠٬٠٠٠ تكرار + Salt عشوائي + مقارنة آمنة زمنياً
- الجلسات: توكن عشوائي ٣٢ بايت، تُخزَّن موقّعة SHA-256، صالحة ٣٠ يوماً
- الكوكي: `HttpOnly` + `SameSite=Lax`
- الصلاحيات: تُفحص في الخادم لكل مسار (وليس في الواجهة فقط)
- عزل SQL: كل الاستعلامات مُعاملة (prepared statements)
